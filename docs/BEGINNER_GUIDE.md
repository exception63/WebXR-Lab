# WebXR-Lab 小白使用教程

这份教程按“完全没有 Web 开发经验”来写。照着顺序操作即可，不需要购买云服务器。

## 一、先理解这套项目怎样工作

- **MacBook 是本地服务器：** 保存项目文件，并把网页发送给头显。
- **Vision Pro 是体验设备：** 使用 Safari 打开 Mac 提供的网页并进入 WebXR。
- **两台设备必须在同一个 Wi‑Fi：** 不建议使用会隔离设备的访客网络。
- **测试时才启动服务：** 测试结束后按一次 `Control + C`，三个服务都会关闭。
- **数据只保存在本地：** 报告不会上传到第三方，也不需要云服务器。

项目位置：

```text
/path/to/WebXR-Lab
```

## 二、第一次使用：准备项目

### 1. 打开终端

在 Mac 上按 `Command + 空格`，输入“终端”，按回车。

### 2. 进入项目文件夹

复制下面整行命令，粘贴到终端，再按回车：

```bash
cd "/path/to/WebXR-Lab"
```

把 `/path/to/WebXR-Lab` 替换为你自己的项目目录；如果路径里有中文或空格，两边的英文双引号不能删除。

### 3. 安装项目依赖

```bash
pnpm install
```

这一步通常只需要做一次。以后如果项目依赖有更新，可以再运行。

### 4. 启动所有本地服务

```bash
pnpm services:start
```

这条命令会同时启动：

- `8080`：Vision Pro 第一次安装证书时使用的引导页。
- `8443`：真正的 WebXR HTTPS 应用。
- `8444`：两台头显共同操作“共振室”时使用的加密局域网房间。

启动时会先自动运行一次生产构建。看到 `Building field-test version local-...` 和 `built in ...` 属于正常流程，不是重复安装。

终端会显示几个网址。当前常用地址通常类似：

```text
证书页：http://192.168.x.x:8080
WebXR：https://192.168.x.x:8443
```

也可以优先尝试更稳定的主机名：

```text
http://<Mac-主机名>.local:8080
https://<Mac-主机名>.local:8443
```

保持这个终端窗口打开。终端没有继续出现文字并不代表卡住，而是服务正在等待 Vision Pro 访问。

## 三、第一次使用：给 Vision Pro 安装证书

证书一般只需安装一次。已经安装并开启完全信任时，可以跳到下一节。

1. 在 Vision Pro Safari 打开终端显示的 `http://...:8080` 地址。
2. 点“下载描述文件”并允许下载。
3. 立即打开 Vision Pro 的“设置”，不要去“文件”App 查找。
4. 在 Apple Account 账户信息下方点“已下载描述文件 / Profile Downloaded”。
5. 确认名称为 **WebXR-Lab Local HTTPS**，点右上角“安装”。
6. 打开“设置 → 通用 → 关于本机 → 证书信任设置”。
7. 为 **WebXR-Lab Local Development CA** 开启完全信任。

下载描述文件后出现黄色感叹号和英文提示是正常的，表示“已经下载，请到设置审查并安装”，不是失败。

待安装描述文件约 8 分钟后会被系统自动删除。如果设置中没有“已下载描述文件”，回到 Safari 重新下载一次，然后立即打开设置。

切勿向任何设备发送下面的私钥文件：

```text
.certs/rootCA-key.pem
```

## 四、每次测试 Vision Pro

### Mac 上

1. 打开终端。
2. 进入项目目录：

   ```bash
   cd "/path/to/WebXR-Lab"
   ```

3. 启动全部服务：

   ```bash
   pnpm services:start
   ```

4. 保持终端窗口打开。

### Vision Pro 上

1. 确认与 Mac 连接同一个 Wi‑Fi。
2. Safari 打开：

   ```text
   https://<Mac-主机名>.local:8443
   ```

3. 如果 `.local` 地址打不开，改用终端显示的 `https://192.168.x.x:8443` 地址。
4. 等待能力扫描完成，确认页面显示 WebXR 和 Immersive VR 可用。
5. 点“进入 VR 探针”。
6. 按系统提示允许 WebXR 和手部追踪。
7. 进入 Hub 后会看到六个共同层门户：手势序章、光之织机、动力工坊、口袋宇宙、声音花园、共振室。
8. 注视任一门户并捏合即可进入；每个展项都有“返回 Hub”按钮，不会结束整个 XR 会话。
9. 最后使用“退出并保存至 Mac”结束会话。

## 五、退出场景并保存报告

现在有两种退出方式：

1. 注视场景下方的 **“退出并保存至 Mac”** 按钮，然后捏合。
2. 使用 Vision Pro 的系统退出方式。

无论使用哪一种，退出后项目都会自动把本次报告保存到 Mac，不必再寻找网页底部的保存按钮。

报告保存在：

```text
WebXR-Lab/reports/local/
```

每次报告都是一个 `.json` 文件。退出后看到页面提示“报告已保存到 Mac”才代表写入成功。

页面上的“保存至 Mac”仍然保留，可用于手动再次保存；“导出 JSON”会把报告下载到当前设备，作为备用。

## 六、测试结束：关闭所有服务

1. 回到刚才运行 `pnpm services:start` 的终端窗口。
2. 同时按键盘上的 `Control + C`。
3. 看到下面的提示并重新出现终端命令行，就表示三个服务都已关闭：

   ```text
   Stopping all WebXR-Lab services...
   ```

不要输入字母 `Control`；要按住键盘左下角的 `control` 键，再按一次 `C`。

想进一步确认时，可以分别运行：

```bash
lsof -nP -iTCP:8080 -sTCP:LISTEN
lsof -nP -iTCP:8443 -sTCP:LISTEN
lsof -nP -iTCP:8444 -sTCP:LISTEN
```

三条命令都没有输出，表示服务已关闭。

## 七、重点展项

### 共振室：两台设备共同操作

Mac 的 8444 服务运行时，两台头显进入“共振室”会看到同一个核心状态：

1. 任一设备注视核心并捏合，颜色、能量和 revision 会同步到另一台。
2. 页面不会上传身份信息，只使用本次浏览器会话里的匿名 `guest-xxxxxx` 编号。
3. WSS 暂时断开时，装置仍可单机触发，并显示“单机降级”。
4. Mac 房间恢复后客户端会自动重连；离开展项就主动断开，不在后台保持网络活动。

### Vision Pro：空间布景

在普通网页的“空间布景”卡片中：

1. 先等待三维模型加载完成。
2. visionOS 27 Safari 支持沉浸网页环境时，“进入空间布景”按钮会自动启用。
3. 点按按钮后，轨道庭院会以真实米制环绕网页窗口展开。
4. 使用网页上的“退出空间布景”，或 Vision Pro 的 Digital Crown，都能返回页面。

若按钮保持灰色，说明当前浏览器只支持图片或模型预览，不是安装失败。不要在 Chrome 或 iPhone 上期待 visionOS 专属入口。

### Quest 3：MR 实验场

Quest Browser 报告支持 `immersive-ar` 时，“进入 Quest MR 实验场”按钮会启用：

1. 进入后缓慢看向桌面或地面。
2. 等薄荷色圆环稳定在真实表面上。
3. 捏合手势或控制器选择键会依次放置三种虚拟构件。
4. 浏览器支持 anchor 时对象会绑定空间锚点；不支持时只在本次会话参考空间中保持。
5. 场景最多保留 18 个对象，继续放置会自动回收最早的对象。

Quest 目前不在身边，因此上述流程已经由代码、测试和构建检查验证，但仍要在最后的真机阶段确认实际 Browser 版本提供哪些 MR 特性。

## 八、Mac 发热怎么办

单纯监听 8080、8443 和 8444 端口通常只消耗很少资源。Mac 发热更常见的原因包括：

- Xcode 的 Vision Pro / xrOS Simulator 仍在运行；
- Chrome、Claude、Codex 等应用正在执行高负载任务；
- `WindowServer` 正在处理多个高分辨率窗口；
- 项目刚完成 TypeScript 构建或其他后台任务；
- 同步盘正在同步大量文件。

当前检查中，三个项目端口都已关闭，而 xrOS Simulator、WindowServer 和多个桌面应用仍占用明显 CPU，因此这次发热不是 WebXR 本地服务单独造成的。不使用模拟器时，可以正常退出 Xcode Simulator。

测试结束后仍建议关闭 WebXR-Lab 服务，这样不会留下不必要的开发进程。

## 九、场景卡顿怎么办

先做下面几件事：

1. 退出并重新进入场景，观察卡顿是否持续。
2. 关闭 Vision Pro 中不需要的其他窗口。
3. 确认 Vision Pro 没有处于低电量或高温状态。
4. 完成至少 20 秒双手测试后退出，让报告自动保存。
5. 把页面显示的报告文件名告诉开发者。

项目已进行第一轮性能优化：

- 双手关节改为实例化绘制，大幅减少 draw call；
- 移除每帧复制大型帧时数组的操作；
- 降低诊断页面在沉浸期间的刷新频率；
- 默认使用 `85%` 的平衡渲染档；若仍卡顿，可在进入 XR 前选择 `72%` 的“流畅”档。

真机是否改善仍需要下一次 Vision Pro 测试确认。

## 十、常见问题

### Vision Pro 打不开 8443

- 确认 Mac 上的 `pnpm services:start` 仍在运行。
- 确认两台设备在同一个 Wi‑Fi。
- 尝试终端显示的数字 IP 地址。
- 确认根证书已经安装并开启“完全信任”。

### IP 地址变了，证书报错

优先使用终端显示的 `<Mac-主机名>.local`。如果只能用新 IP，可以在 Mac 项目目录运行：

```bash
pnpm certs -- --force
```

这会重新生成证书，随后必须在 Vision Pro 删除旧描述文件并重新安装新描述文件、重新开启完全信任。

### 退出后没有生成报告

- 确认 Mac 的 8443 服务在退出时仍然运行。
- 查看普通网页上的状态提示。
- 检查 `reports/local/` 文件夹。
- 必要时点网页上的“保存至 Mac”重试。

### WebXR 按钮不可用

- 页面必须通过受信任的 `https://` 地址打开。
- 能力页面中的“安全上下文”“WebXR API”“Immersive VR”都应显示可用。
- visionOS Beta 更新后，Safari 的实验功能状态可能发生变化。

## 十一、开发者自检

修改代码后运行：

```bash
pnpm verify
```

它会依次执行 39 项单元测试、TypeScript/生产构建和资源预算检查。全部显示 `PASS` 后再启动服务进行真机验证。
