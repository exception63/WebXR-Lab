# 真机测试协议

## 测试前准备

- MacBook、Quest、Vision Pro 连接同一支持设备互访的 Wi‑Fi；访客网络通常会隔离设备，不适合测试。
- Mac 防火墙允许项目 Node 进程接受入站连接。
- 记录 Mac 的 `.local` 主机名和局域网 IP。
- 头显系统与浏览器版本写入报告，不只写设备型号。
- 确认使用由项目启动脚本显示的 HTTPS 地址。

### 证书
1. 通过 Mac 的 8080 安装页下载 `WebXR-Lab-Root-CA.mobileconfig`。
2. 立即在“设置”中安装配置描述文件。
3. 在证书信任设置中为该根证书启用完全信任。
4. 打开项目 HTTPS 地址，确认无证书警告且页面报告 `isSecureContext === true`。

### Web Inspector
1. visionOS：Settings → Apps → Safari → Advanced → Web Inspector。
2. Vision Pro：General → Remote Devices，保持页面可见。
3. Mac Safari Develop 菜单中选择设备并配对。
4. 从设备子菜单打开当前页面的 Web Inspector。

### 必测场景
- 拒绝与允许 WebXR 会话权限。
- 拒绝与允许 hand tracking 权限。
- 不请求 hand tracking 时的 transient pointer。
- 请求 hand tracking 后的输入源排列和选择事件。
- 单手、双手、手离开视野、重新进入视野。
- 进入/退出 10 次，检查 session 与音频恢复。
- `<model>` 的内联预览、`requestImmersive()`、Digital Crown 退出。

### M2 Hub 与手势序章

1. 进入 `immersive-vr` 后，确认能同时看到 4 个门户、能力核心和退出按钮。
2. 注视“手势序章”门户并捏合；再确认其余五个共同层门户都能进入对应展项，不会进入空场景。
3. 依次命中青色、蓝色、琥珀色三个目标，记录每次捏合是否只推进一步。
4. 完成后确认面板显示“校准完成”。
5. 注视“返回 Hub”并捏合；确认 XRSession 没有结束，门户重新出现。
6. 再次进入“手势序章”，确认进度从 `1/3` 重新开始。
7. 使用“退出并保存至 Mac”结束；再用系统方式退出一次，两种方式都应自动生成报告。
8. 报告中应出现 `experience-entered`、三次 progress/completed、`hub-returned` 与最终 `session-ended`。
9. 每个页面停留约 20 秒，主观比较卡顿，并记录 p50、p95、maximum 帧时间。

## Meta Quest

### 连接
1. 先测试 `.local` 地址；若解析失败，使用局域网 IP。
2. 完成 CA 安装/信任验证；若系统阻止用户 CA，记录系统和 Browser 版本，不采用绕过安全上下文的假方案。
3. 确认页面报告 `isSecureContext === true` 和 `navigator.xr` 存在。

### 必测场景
- `immersive-vr` 与 `immersive-ar`。
- 手部追踪、控制器、手与控制器切换。
- 单手、双手、遮挡、追踪丢失与恢复。
- passthrough 背景与真实房间边界。
- 对每个 optional feature 单独请求，再测试可用组合。
- 进入/退出 10 次，浏览器最小化/恢复一次。
- 10 分钟性能采样与温度/降频迹象。

### Quest MR 实验场

- [ ] AR 会话显示真实环境，VR 地板、Hub 与黑色背景均不遮挡 passthrough。
- [ ] 缓慢看向桌面或地面后出现稳定的薄荷色 hit-test 圆环。
- [ ] 手势捏合与控制器选择都能在圆环位置放置构件。
- [ ] 连续放置 19 次后最多保留 18 个对象，最旧对象和 anchor 被回收。
- [ ] 报告记录 hit-test、planes、meshes、anchors 的实际数量；缺失能力时界面明确降级。
- [ ] 场景内退出与系统退出均结束会话、清理 anchor 并自动保存报告。

## 共同测试脚本

1. 打开诊断页并导出“进入 XR 前”报告。
2. 进入 VR，依次执行 aim、select、grab、双手缩放、菜单、退出。
3. 在动作过程中故意让一只手离开视野，再恢复。
4. 记录所有 `inputsourceschange` 与错误。
5. 进入每个已允许展项，停留至少两分钟。
6. 连续切换展项，观察内存、GPU 资源与事件重复触发。
7. 关闭互联网连接但保留本地 Wi‑Fi，重复核心流程。
8. 导出“测试后”报告并保存到项目的本地测试记录目录。

## 通过标准

- 安全上下文、会话、输入、音频和退出均可重复工作。
- 输入源变化不会导致展项崩溃或失去返回入口。
- 不支持的功能在进入前显示为不可用。
- 任何隐私权限拒绝都有可恢复路径。
- 性能不达标时自动降低质量，而不是牺牲头部跟踪流畅度。
