# 里程碑与验收

里程碑以“通过闸门”推进，不以堆积功能推进。若真机事实与规划冲突，先修改能力矩阵和架构，再继续做展项。

## M0：规划基线

交付：
- 产品蓝图
- 技术架构
- 设备能力矩阵
- 真机测试协议
- 项目任务与进度文件

验收：
- 共同层、Quest 增强层、Vision Pro 增强层边界清楚。
- 无云服务器方案与最大风险已记录。

状态：**已完成**

## M1：设备能力探针

交付：
- TypeScript/Vite/Three.js 最小项目
- 桌面诊断页
- 本地 HTTPS/WSS 启动脚本与二维码
- VR/AR 会话探针
- 输入源与手部关节可视化
- JSON 报告导出

验收闸门：
- Quest 和 Vision Pro 都能通过 HTTPS 打开同一 Mac 服务。
- 两台设备均生成报告并成功进入 `immersive-vr`。
- Vision Pro 可看到 transient pointer 与持续手部输入。
- Quest 完成 VR/AR、手与控制器的实际矩阵。
- 已记录浏览器/OS 版本、证书步骤与调试方法。

状态：**代码完成；Vision Pro 首轮启动通过，Quest 与新版完整矩阵待集中验收**

## M2：共同层垂直切片

交付：
- Hub、门户和统一返回流程
- 手势序章
- 光之织机
- 动力工坊
- 口袋宇宙基础版
- Input Adapter 与展项 Registry

验收闸门：
- 两台设备的共同展项无需设备专属业务分支即可运行。
- 选择、抓取、双手操作、追踪丢失恢复和退出均通过。
- Quest 达到 72 FPS 目标；Vision Pro 达到浏览器帧预算。
- 连续切换展项 20 次无明显 GPU/事件监听器泄漏。

状态：**六个共同层展项已完成；硬件性能和稳定性闸门待集中验收**

## M3：设备增强切片

交付：
- Quest MR 实验台
- Vision Pro 27 空间布景
- 设备不支持时的清晰说明与预览

验收闸门：
- Quest passthrough 展项通过真实房间测试。
- Vision Pro `<model>` 环境可从网页预览进入并正常退出。
- 两个增强展项不污染共同层架构。

状态：**代码完成；两台设备增强能力待集中验收**

## M4：体验扩展

候选交付：
- 声音花园
- 不可能门户
- 活体界面
- 手势乐团
- 渲染显微镜

验收闸门：
- 每个展项有独立 manifest、资源预算、舒适度等级和设备记录。
- 首次使用引导与错误恢复一致。

状态：**声音花园、首次引导、舒适设置与讲解模式已完成；其他候选展项保留为未来扩展**

## M5：局域网共创

交付：
- Mac WSS 房间服务
- 两台设备同步同一可交互装置
- 网络断开时单机降级

验收闸门：
- 不连接互联网时，同一 Wi‑Fi 下仍可协作。
- 网络抖动不导致对象永久分叉或场景卡死。
- 服务停止后共同层单机展项仍可使用。

状态：**WSS 房间、共振室与单机降级已完成；双头显同步待集中验收**

## M6：演示版

交付：
- 一键启动、地址/二维码、设备指南
- 缓存与断网演示模式
- 完整性能回归与故障排查
- 展项导览和演示顺序

验收闸门：
- Mac 重启后可按文档在 5 分钟内恢复服务。
- Quest 与 Vision Pro 各完成 30 分钟稳定性测试。
- 从首次打开到进入任一共同展项不超过三个明确操作。

状态：**一键生产构建/启动、缓存、资源预算与文档已完成；只剩最终硬件闸门**
